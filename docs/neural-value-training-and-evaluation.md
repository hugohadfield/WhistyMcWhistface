# Whist learned-value MLP: training, validation, and playing-strength evaluation

This is a complete **supervised imitation of the Monte Carlo teacher**
pipeline with an explicit distinction between teacher imitation and
real playing strength. The network predicts an **eight-bin additional
tricks won distribution for every legal card**, from the *acting
player's own* `InformationState`. It cannot see real hidden hands.
The teacher continuation policy is part of the experimental definition.

## End-to-end workflow

From repository root, with optional PyTorch installed:

```bash
python -m pip install -r requirements-ml.txt

# 1. Generate whole, genuinely played games (all player observations).
python -m benchmarks.generate_training_games \
  --games 2000 --players 3 --seed 20262001 \
  --workers 16 --agents random,mc_random,mc_aware --rollouts 128 \
  --output-dir data/played-games

# 2. Label counterfactual cards using persistent state-parallel CPU MC.
python -m benchmarks.export_training_labels \
  --traces 'data/played-games/*.jsonl' \
  --output-dir data/whist-mc-1024 \
  --rollouts 1024 --workers 16 --policy bid_aware_2 \
  --seed 20262001 --state-batch-size 4 --shard-size 256

# 3. Train on GPU if available; otherwise CPU, with validation.
python -m benchmarks.train_value_model \
  --dataset data/whist-mc-1024 \
  --output-dir runs/whist-value-v1 \
  --device auto --batch-size 1024 --epochs 30 --patience 8 \
  --hidden-size 128 --residual-blocks 2 --lr 0.0003

# 4. Evaluate exactly once on unseen deal-group test examples.
python -m benchmarks.evaluate_value_model \
  --dataset data/whist-mc-1024 \
  --checkpoint runs/whist-value-v1/best.pt --split test \
  --output runs/whist-value-v1/test-metrics.json

# 5. Assess competitive score against frozen 1024-rollout MC.
python -m benchmarks.neural_vs_monte_carlo \
  --checkpoint runs/whist-value-v1/best.pt \
  --games 250 --rollouts 1024 --mc-policy bid_aware_2 \
  --workers 8 --device cpu --bootstrap 5000 \
  --csv runs/whist-value-v1/tournament.csv \
  --json runs/whist-value-v1/tournament-summary.json
```

**Important:** step 2 is typically the largest CPU cost. You do not
need a GPU to generate labels; PyTorch training is much smaller.
No full 2000-game dataset or 250-game tournament is generated by the
CI smoke test.

## Training

`benchmarks.train_value_model` reads one compressed `.npz` shard at a
time, shuffles training shard order and rows reproducibly each epoch and
uses AdamW, gradient clipping, and distributional soft-label cross entropy.
It checks the feature and label schemas and enforces nonempty **whole-deal
train, validation and test splits**. It never uses test data for model
selection.

Use `--device auto` to choose CUDA, Apple Metal MPS or CPU in that
order; force `--device cpu` for CI. Defaults: 128 hidden units, two
residual blocks (316,448 parameters), batch size 512, 30 epochs,
learning rate 3e-4 and patience 8.

Outputs:
- `best.pt`: lowest **validation action cross entropy** checkpoint,
  ready to use with NeuralValuePlayer.
- `last.pt`: final epoch checkpoint for diagnosis.
- `history.csv`: per-epoch training CE, validation CE/MAE/RMSE, card
  choice agreement, and expected-score regret.
- `training-config.json` and `result.json`: exact hyperparameters,
  teacher provenance, parameter count, and checkpoint selection.

Checkpoints use `torch.load(..., weights_only=True)` and validate
checkpoint version, feature schema, dimensionality and architecture.
Changing feature representation requires a new checkpoint schema.

## Held-out metrics: what they do and don't say

`benchmarks.evaluate_value_model` calculates:

| Metric | Interpretation |
|---|---|
| Action cross entropy | Per-legal-card soft-label classification error |
| Action Brier | Sum of eight squared probability-bin errors per legal card |
| Expected round-score MAE/RMSE | Predicted vs MC teacher expected score in points |
| Teacher top-1 card agreement | Exact argmax agreement including deterministic ties |
| Teacher-optimal agreement | Allows ties within 1e-6 MC point |
| Teacher expected regret/decision | Teacher's highest Q minus teacher Q of model's chosen card |

The label counts are *sampled estimates*, not perfect-play ground truth.
These are **teacher-relative** metrics. The test script evaluates the
dataset's `test` split by default and refuses teacher-policy mismatches.
Use a separate higher-rollout **test-only** dataset if you want more
precise reference labels (same feature schema and teacher semantics).

A small held-out test split is not meaningful: generate sufficient
independent deal groups and keep all seat-swapped games together. Never
train on the test split or tune decisions using the tournament results
without reserving a fresh independent benchmark.

## Actual game play and paired tournaments

`NeuralValuePlayer` is a standard `Player` subclass, requiring a
trained `checkpoint`. It inherits **the exact same trump selection and
bidding algorithms** as `MonteCarloPlayer` and replaces *only card
selection*. It loads its network lazily, caches it in memory and always
plays legal cards. It uses only `game.observe(player_id)` for features.
For forced actions it doesn't need model inference.

The paired 3-player tournament runs **two full 13-round matches per
deal seed**, swapping the seats occupied by the neural and MC players.
The third seat is occupied by an unchanged random player. Each round's
deal uses a fixed seed independent of prior policy RNG consumption, so
both variants get matched initial hands in each pair.

Reported mean score difference and bootstrap confidence intervals are
computed over **deal pairs**; the per-game raw CSV is also kept.
This is a three-player benchmark, not evidence of strength for all 2–7
player formats. You can vary `--mc-policy` and `--rollouts`, but always
record them, since they fundamentally change the baseline.

A model that imitates an MC teacher with weak random continuations may
still play poorly against stronger opponents. Competitive evaluation,
preferably against multiple opponent styles, is indispensable.

## GitHub Actions / local workstation

The opt-in `neural_training_end_to_end` PR job:
1. Installs **CPU-only PyTorch** and runs real-data integration tests.
2. Creates eight independently seeded full games.
3. Labels all non-forced decision states at a cheap 16-rollout budget,
   with split groups containing train, validation and test.
4. Trains the small MLP for three CPU epochs.
5. Evaluates the untouched test split.
6. Plays a **two-game paired** neural vs MC head-to-head.
7. Archives checkpoint, histories, metrics, raw traces, shards and scores.

This is a **pipeline test**, not a claim that the tiny model is strong.
GitHub Actions artifact retention is 14 days; copy anything useful to
durable storage. For a serious dataset and training run, use a local CPU
server for parallel labels and a GPU for faster experimentation on the
model, but the MLP does not *require* a GPU.

Suggested research stages: calibrate on 100–500k positions; measure
held-out Q regret; then run matched 1024-rollout tournaments. Only scale
toward millions of examples if those metrics warrant it.
